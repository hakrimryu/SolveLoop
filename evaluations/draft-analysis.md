# 下書き10種に対する分析者の所見

対象は最初の基準線の各初回成功。利用者のレビューは全10種**未実施**。以下は原文と生成抜粋を比較した分析者の指摘であり、承認や人による品質確認完了の記録ではない。比較原文・生成案・未記入の確認欄は結果ディレクトリの`draft-review.md`にある。

| 種類 | 根拠への忠実さ・手順 | 条件・注意の問題 | 修正の見立て（未承認） |
| --- | --- | --- | --- |
| D01 印刷 | 2操作を原文の順で抽出。2根拠から同じ操作を重複抽出していない | 他人のジョブを削除しない制限が全生成欄から欠落 | 安全制限を補完する修正が必要 |
| D02 閲覧申請 | 2操作は残る。句点を含まない連続抜粋のため自動の完全一致検査は「未検出」になるが、操作そのものの欠落ではない | 承認前の暫定付与禁止が全生成欄から欠落 | 禁止条件を追加し対象部署・期限を確認 |
| D03 打刻 | 対象日→実時刻と理由→上司提出の順は原本に対応 | 締め後の自己修正禁止がstepsに入りcautionsは空 | 操作と制限を分けて表示する修正が必要 |
| D04 育児勤務 | 人事申請→調整・受付確認は原本に対応。audienceに「対象:」と句点が付いた原文範囲を抽出 | 受付前の変更禁止がstepsに入りcautionsは空 | 注意欄へ移す。対象の表記を整える |
| D05 空調 | 利用中止・退避→総務連絡を抽出し、解決後の状態を初期症状に移していない | 分電盤・室外機の操作禁止が全生成欄から欠落。原因等の追加確認を多数提示 | 安全制限を追加し、原因究明が必須かを人が判断 |
| D06 請求 | 照合→保留・写し送付は対応。2根拠の同操作を重複抽出していない | 確認前の登録禁止がstepsに混在。個別の取引先名の不足を指摘するが一般的手順の公開に必要か要判断 | 制限を分離し不要な不足指摘を整理 |
| D07 仮払 | 領収書・残額→期限内提出は原本に対応 | 私用支出禁止をmissing_informationへ移し、既知の制限を不足情報と誤分類 | 既知の規則を注意へ戻す修正が必要 |
| D08 冷凍便 | 連絡→指定容器・零下二十度・予約便の順は原本に対応。複数根拠の重複なし | 常温棚へ置かない制限が全生成欄から欠落。容器の詳細は原本にないため確認が必要 | 制限補完と容器・予約条件の確認が必要 |
| D09 QR連携 | 人事連絡→有効化・再読込の順は対応 | 試験対象外は手動という条件がstepsに混在。試験対象の範囲は利用者が原本で確認すべき | 対象・例外の確認と注意欄の修正が必要 |
| D10 操作不明 | stepsを空にして操作を創作していない。対象不明の定型表現を使用 | 原本自体に具体操作・対象がない。復旧確認だけでは手順書にできない | 追加調査まで公開保留が妥当か利用者確認が必要 |

引用可能な連続文字列であることと、必要な制限を落とさず安全に再利用できることは別の検査である。9種の注意を単純な「9件すべて内容欠落」と数えず、他欄への混在5種と全欄からの欠落4種を分ける。cautions欄は9種とも空で、形式上の成功30/30を内容品質100%とはしない。audienceの完全一致不一致も、接頭辞や句点を含むだけなら適用条件の誤りと断定しない。

同一入力の3回生成は全出力hashを別途比較する。ここでの指摘をもとに保留入力の正解・prompt・thresholdを変更していない。実際の採否・修正必要度・確認者・日時は利用者がレビュー資料へ記入するまで未確定。
